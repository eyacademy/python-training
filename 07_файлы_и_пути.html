      Как это выглядит в коде
      
Пути через pathlib, чтение и запись таблиц

    

    


from pathlib import Path
import pandas as pd

DATA_DIR = Path("data")
RESULT_DIR = Path("результаты")
RESULT_DIR.mkdir(exist_ok=True)      # создать папку, если её нет

df = pd.read_excel(DATA_DIR / "добыча_2026.xlsx", sheet_name="Добыча")
wells = pd.read_csv(DATA_DIR / "скважины.csv", sep=";", encoding="utf-8-sig")

df.to_excel(RESULT_DIR / "отчёт_добыча_2026.xlsx", index=False)

      

        
Знак / между частями пути в pathlib склеивает папки. Python сам поставит \ на Windows и / на macOS, поэтому один и тот же код работает на любом компьютере.

        
Относительный путь data/... считается от папки, где запущен терминал. В VS Code откройте папку проекта целиком: File, Open Folder.

        
Надёжный вариант для скрипта: BASE = Path(__file__).parent, затем BASE / "data" / "добыча_2026.xlsx". Путь считается от места, где лежит сам .py-файл.

      

    

  


  

    

      Типичная ошибка
      
Путь с обратными слешами и открытый в Excel файл

    

    

      
Так ломается


df = pd.read_excel("C:\Users\aigerim\new\data.xlsx")
# \U и \n внутри строки Python читает как спецсимволы

df.to_excel("результаты/отчёт.xlsx")
# PermissionError: файл открыт в Excel

      
Так работает


df = pd.read_excel(Path("data") / "data.xlsx")
# относительный путь, без обратных слешей

# закройте отчёт в Excel перед запуском скрипта
df.to_excel(Path("результаты") / "отчёт.xlsx")

    

    
Абсолютный путь с диском C:\ работает только на одном компьютере. Коллега на macOS или с другим именем пользователя его не откроет. Держите данные в папке проекта и пишите относительные пути.
