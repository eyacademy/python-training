Ошибки и traceback

Когда скрипт падает, Python печатает traceback: отчёт о том, что сломалось и где. Он выглядит страшно, но читать нужно только две строки. Ошибка это нормальная часть работы, а не поломка компьютера.

Метафора

Traceback это записка от Python. Читаем её снизу вверх: последняя строка говорит, что случилось. Строка выше с line N и именем вашего файла говорит, где.

1Последняя строкаТип ошибки и короткое описание: KeyError: 'Нефть'.
2Строка с вашим файломИщите File "...otchet.py", line 14. Строки из site-packages это внутренности библиотек, их пропускаем.
3Код под нейPython показывает саму строку и подчёркивает ^^^^ место, где споткнулся.

      Как это выглядит в коде
      
try/except: поймать ожидаемую ошибку и сказать понятными словами

    

    


from pathlib import Path
import pandas as pd

DATA_FILE = Path("data") / "добыча_2026.xlsx"

try:
    df = pd.read_excel(DATA_FILE, sheet_name="Добыча")
except FileNotFoundError:
    print(f"Не найден файл {DATA_FILE}. Откройте в VS Code папку проекта.")
    raise SystemExit(1)

      

        
try означает «попробуй». except означает «если случилась вот эта ошибка, сделай вот это». Так скрипт пишет человеку понятный текст вместо длинной записки.

        
Ловите только ту ошибку, которую ждёте. except: без имени прячет все ошибки подряд, и настоящую причину потом не найти.

        
Просите ИИ добавлять такие проверки: «добавь понятные сообщения, если нет файла, листа или колонки».

      

    

  


  

    

      Типичная ошибка
      
Читать записку сверху и чинить библиотеку

    

    
Верхние строки часто указывают внутрь pandas: site-packages\pandas\core\frame.py. Там ничего исправлять не нужно, библиотека работает правильно. Ошибка почти всегда в вашей строке: неверное имя колонки, путь, тип данных. Спускайтесь вниз до последней строки, потом ищите выше своё имя файла.
